# Multi-Database Diagnostic Viewer & Table Diff Desktop App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a standalone Python desktop application for diagnosing multi-engine BI databases (PostgreSQL, MSSQL, Oracle, SQLite, H2 format 3), organizing projects & frequent queries, rendering query results in a Tabulator datagrid with multi-column grouping and sorting, and generating cross-database table diff & sync SQL scripts.

**Architecture:** A Python application core manages database connectors, metadata storage (SQLite), and cross-database table diffing. A local lightweight desktop API bridges the Python core to a responsive desktop webview UI utilizing Tabulator for zero-license-cost multi-column grouping, virtual scrolling, and multi-result tabs alongside a SQL editor with query history.

**Tech Stack:** Python 3, PySide6 / `pywebview`, SQLite (local metadata), `psycopg` (PostgreSQL), `pymssql` (MSSQL), `python-oracledb` (Oracle thin mode), `sqlite3` (SQLite), H2 2.x JDBC runner (H2 format 3 embedded), Tabulator 5.x (datagrid), CodeMirror (SQL editor), pytest.

**Spec:** `docs/superpowers/specs/2026-10-30-dbviewer-design.md`

## Global Constraints

- Python 3.10+ compatible implementation.
- All application configuration and metadata stored under `~/.dbviewer/dbviewer.db`.
- Tabulator (MIT open source) must be used for datagrid grouping without commercial license dependencies.
- Table diff engine must support cross-engine comparisons across all 5 databases (Postgres, MSSQL, Oracle, SQLite, H2).
- Diff SQL generator must output valid target dialect DDL/DML enclosed in explicit transaction blocks (`BEGIN ... COMMIT`).
- Safe execution row limit default (5,000 rows) on ad-hoc diagnostic queries.

## Review Focus

1. **Table without a primary key in diff:** When a table lacks a defined primary key, comparator must accept user-specified key columns or raise an informative `MissingPrimaryKeyError` rather than crashing.
   * *Pinned to:* Task 4, Step 1 (`test_diff_missing_primary_key_handling`)
2. **NULL value equivalence in row comparisons:** Diff engine must treat `None == None` as identical and properly format `IS NULL` / `NULL` in generated SQL without falsely flagging unmodified NULL columns.
   * *Pinned to:* Task 4, Step 1 (`test_diff_null_values_equality`)
3. **Quote escaping in generated SQL statements:** Values containing single quotes (e.g. `"O'Reilly"`, `"line1\nline2"`) must be escaped properly according to target dialect syntax (`'O''Reilly'`) to prevent SQL injection and syntax errors.
   * *Pinned to:* Task 5, Step 1 (`test_sql_generator_quotes_escaping`)
4. **Multi-statement scripts with comments and trailing semicolons:** SQL runner must split and execute valid queries while ignoring comments and blank statements, returning result sets only for statements producing rows.
   * *Pinned to:* Task 2, Step 1 (`test_execute_multi_query_with_comments_and_empty_statements`)
5. **Safe row limits on unbounded queries:** Diagnostic queries returning massive row sets must adhere to `max_rows` cap without loading full tables into memory.
   * *Pinned to:* Task 2, Step 1 (`test_query_execution_max_rows_enforcement`)

  - `diff/`
    - `models.py`: Data models for schema diff, row diff (inserts, updates, deletes), diff results.
    - `comparator.py`: Cross-engine schema comparison and key-indexed row diff algorithm.

**Interfaces:**
- Consumes: `TableSchema`, `ColumnInfo` (from Task 2)
- Produces:
  ```python
  @dataclass
  class ColumnDiff:
      column_name: str
      source_type: Optional[str]
      target_type: Optional[str]
      status: str  # "MATCH", "ADDED_IN_SOURCE", "REMOVED_IN_SOURCE", "TYPE_MISMATCH"

  @dataclass
  class SchemaDiff:
      source_table: str
      target_table: str
      column_diffs: List[ColumnDiff]
      missing_in_target: List[ColumnInfo]
      extra_in_target: List[ColumnInfo]
      type_mismatches: List[Tuple[str, str, str]]

  @dataclass
  class RowDiff:
      key_values: dict
      action: str  # "INSERT", "UPDATE", "DELETE"
      diff_values: dict  # {col: (old_val, new_val)} for UPDATE; full dict for INSERT/DELETE

  @dataclass
  class TableDiffResult:
      schema_diff: SchemaDiff
      key_columns: List[str]
      inserts: List[RowDiff]
      updates: List[RowDiff]
      deletes: List[RowDiff]

  class TableComparator:
      def compare_schemas(self, source_schema: TableSchema, target_schema: TableSchema) -> SchemaDiff: ...
      def compare_data(self, source_rows: List[dict], target_rows: List[dict], key_columns: List[str]) -> Tuple[List[RowDiff], List[RowDiff], List[RowDiff]]: ...
      def compare_tables(self, source_conn: BaseDatabaseConnector, source_table: str, target_conn: BaseDatabaseConnector, target_table: str, user_keys: Optional[List[str]] = None) -> TableDiffResult: ...
  ```
